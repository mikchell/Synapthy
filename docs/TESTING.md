# テスト方針

## 現状

自動テスト（単体テスト・E2Eテスト）は未導入。`package.json` にもテストランナー（Vitest・Jest・Playwright等）は入っていない。品質担保は以下の2つに依存している。

```bash
npm run build   # tsc -b でビルド（型エラーがあれば失敗する）
npm run lint     # oxlint
```

新しい変更を加えたら、最低限この2つを通すこと。

## 手動確認の基本フロー

テストが無いため、機能追加・修正時は以下を手動で確認する（`npm run dev` でローカル起動）。

1. **未ログイン状態**（localStorageのみ）でシートを作成・編集し、リロードしても内容が保持されるか
2. **Googleログイン**後、同じ操作がSupabaseに同期され、別タブ/別ブラウザでも反映されるか
3. ネットワークタブ等で、**保存のタイミング**（即時 or デバウンス）が意図通りか。特にゴミ箱・スターなど「リロードで消えてはいけない」操作は、変更直後すぐにリロードしても状態が保持されることを確認する（[data-structure.md](./data-structure.md#データフロー) 参照）
4. **ライト/ダーク**両方の表示崩れがないか
5. **モバイル幅**での表示・操作（ホーム画面、画像貼り付けなど）

## 今後テストを導入する場合の指針

- まず対象にすべきはロジックが集中している純粋関数：`src/features/mindmap/store/mindmapStore.ts` のレイアウト計算・整列アルゴリズム、`src/features/home/utils/`（`sheetSelectors.ts` など）
- `useSheetsSync.ts` のデバウンス/即時保存の分岐はリグレッションが起きやすい箇所なので、ユニットテストでカバーする価値が高い
- UIの自動テストを入れる場合は、Vite環境と相性のよいVitest + React Testing Libraryを軸に検討する（現時点では未決定・未導入）
