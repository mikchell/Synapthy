# PRD（Product Requirements Document）

## プロダクト概要

Synapthy（シナプシー）は、アイデアをつなげるマインドマップアプリ。ノードを右方向に展開し、思考の流れを視覚化する。名前の由来は [README.md](../README.md#名前の由来) を参照。

## コンセプト

断片的な知識やメモを、ノードとして記録しつなげることで、新しい気づきや体系的な理解へと発展させる。中心テーマから世代ごとに右へ展開する構造（ロジックツリー）を軸に、整列の手間をアプリ側で吸収し、ユーザーは「書く・つなげる」ことに集中できるようにする。

## 想定ユーザー

- 自分の考えを整理したい個人ユーザー（アイデア整理、読書メモ、議事録の構造化など）
- ブラウザだけで使えることを求める（インストール不要・Googleログインのみ）
- 複数のマインドマップを並行して管理したいユーザー（ノート代わりに使う想定も含む）

## 現状の主要機能（実装済み）

詳細は [README.md](../README.md#主な機能) を参照。要約すると：

1. **自動整列（Tidy Layout）** — ロジックツリー型シートで、ノードを左右展開レイアウトに自動整頓
2. **ノード編集** — 追加・ラベル編集（太字・文字色を、全体または一部分に）・カラー6色・メモ・枠線/角丸/円形/サイズ・画像添付（中心テーマには付けられない）・シートごとの線の色
3. **Undo / Redo** — 編集操作の履歴管理（シート単位）
4. **ホーム画面** — マップ一覧（枚数に応じてカードの大きさが変わる、サムネイル付き）、サムネイルの選択（同梱のテンプレート56点、または自分の画像）、スター、フォルダ分け（ドラッグ&ドロップ）、ゴミ箱、最近使用した項目
5. **複数シート** — 追加・ゴミ箱への移動・復元・完全削除・リネーム・スター・フォルダ移動。編集画面にも、折りたためるサイドバー（シートの切り替え・新規作成・ゴミ箱・フォルダ移動）がある
6. **範囲選択・複数移動**、**キャンバス操作**（ズーム・パン・ミニマップ）
7. **Googleログイン（Supabase Auth）** とデータ永続化（オフライン時はlocalStorage、ログイン時はSupabaseに同期）
8. **ダークモード**（OS追従＋手動切替）
9. **モバイル対応**（ホーム画面・編集画面・画像貼り付け）
10. **ガイドツアー** — 初めて登録した人向けの、画面上のチュートリアル（スキップ可・「使い方」ボタンから再表示）
11. **書き出し** — 編集中のシートを、PDF（印刷機能で、ベクターのまま1ページに）と Markdown（階層の箇条書き）で書き出す

## データ永続化の要件

- オフライン（未ログイン）でも動作し、データはブラウザのlocalStorageに保持される
- ログイン後は同じデータがSupabaseに同期され、別端末からも継続して編集できる
- **ゴミ箱・スターなどメタ情報の変更は、リロードしても即座に反映されていなければならない**（デバウンス中の消失は不可。[data-structure.md](./data-structure.md#データフロー) 参照）
- ノード・エッジ本体の変更は多少のデバウンス（1秒）を許容し、保存頻度とサーバー負荷のバランスを取る
- 共有端末で、前の人のマインドマップが次の人のアカウントに残ったり、保存されたりしてはならない（端末のキャッシュに持ち主を記録して、別の人のときは捨てる。[SECURITY.md](./SECURITY.md#端末に残るキャッシュの持ち主) 参照）
- 悪意のある利用で、データベースの容量や帯域を使い切られないよう、1人あたりの上限を設ける（シート100枚・ごみ箱含む、1シート2MB、フォルダ50個、名前100文字、画像200枚・1枚2MB）。値は `src/lib/limits.ts` と DB のマイグレーションで同じにそろえる（[DATABASE.md](./DATABASE.md#利用上限悪用対策)）

## 非ゴール（現時点では対象外）

- リアルタイム共同編集（複数人が同時に同じシートを編集する機能）
- マインドマップの他ユーザーへの共有・公開リンク
- Google以外の認証プロバイダ対応
- フォルダの入れ子構造（現状はフラットのみ）
- オフライン編集中のマルチデバイス間コンフリクト解消（現状は最後に書いた側が勝つ想定）

## 品質方針

- 自動テストは未整備（[TESTING.md](./TESTING.md) 参照）。型チェック（`tsc -b`）とlint（oxlint）を最低限のゲートとする
- RLSによるデータ分離を前提に、クライアント側の実装ミスがあっても他ユーザーのデータに到達できないことをDB側で保証する（[SECURITY.md](./SECURITY.md) 参照）
